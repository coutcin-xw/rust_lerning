# 前言

## 为什么学习 Rust？

Rust 是一门**系统级编程语言**，由 Mozilla 研究员 Graydon Hoare 创建，现在由 Rust 基金会维护。它同时做到了三件看似矛盾的事：

1. **内存安全** — 没有空指针解引用、没有悬垂指针、没有数据竞争、没有缓冲区溢出。这些 bug 在编译期就被消灭了，而不是等到生产环境崩溃。
2. **零成本抽象** — 高级语法（迭代器、闭包、泛型）编译后和手写底层代码性能相同。你不必为了性能牺牲可读性。
3. **现代开发体验** — 业界最好的编译器错误信息、出色的包管理器（Cargo）、一流的工具链（rustfmt, clippy, rust-analyzer）。

### Rust 的实际应用

Rust 早已不是"玩具语言"。以下是一些真实案例：

| 领域 | 案例 |
|------|------|
| **操作系统内核** | Linux 内核从 6.1 开始接受 Rust 代码，Android 也在大量使用 |
| **浏览器引擎** | Firefox 的 Servo 引擎（Rust 的诞生地） |
| **云基础设施** | AWS Lambda, Cloudflare Workers, Dropbox 的文件同步引擎 |
| **区块链** | Solana, Polkadot, Sui 等主流链都用 Rust |
| **CLI 工具** | ripgrep, fd, bat, exa/lsd——新一代命令行工具的标配语言 |
| **Web 服务** | 用 axum/actix-web 构建的 API 在性能排行榜上名列前茅 |

### Rust 适合谁？

- **从 C/C++ 转来的开发者**：Rust 给你同样的底层控制力，但编译期就消除内存 bug
- **从 Java/C# 转来的开发者**：Rust 的 Trait 和泛型系统开创性地解决了表达力问题，没有继承的包袱
- **从 Python/JS 转来的开发者**：Rust 帮你理解计算机到底在做什么，同时保持现代的代码组织方式
- **编程初学者**：Rust 的学习曲线陡峭，但编译器是你的私人教师——每一条错误信息都在教你

### Rust 不适合什么？

诚实地说，Rust 不是万能药：
- **快速原型**：Python/JS 更快。Rust 的编译时间和严格的类型系统会让快速试错变得慢。
- **游戏开发**：虽然有了 Bevy 等引擎，但生态远不如 C++/Unity/Unreal。
- **数据科学/ML**：Python 生态（NumPy/Pandas/PyTorch）不可替代。Rust 可作为性能核心的补充。
- **一次性脚本**：如果只需要跑一次，用 Python/Shell。

## 什么是 Rust 2024 Edition？

Rust 有一个独特的概念——**Edition（版次）**。每 3 年左右发布一个新 Edition，允许语言在不破坏向后兼容性的前提下引入语法层面的改进。

关键理解：**不同 Edition 的代码可以无缝互操作**。你在 Rust 2024 项目里可以正常使用 Rust 2015 编写的库，反之亦然。编译器知道如何处理所有 Edition 的语法。

### Rust 2024 Edition 亮点

Rust 2024 Edition 于 **2025 年 2 月随 Rust 1.85.0 稳定发布**，是迄今为止规模最大的 Edition：

| 特性 | 说明 | 影响的章节 |
|------|------|-----------|
| **let chains** | `if let A && let B { }`，链式模式匹配 | 第 6 章 |
| **RPIT 生命周期自动捕获** | `impl Trait` 返回值自动捕获所有生命周期 | 第 8、9 章 |
| **`use<..>` 精确捕获** | 手动控制 `impl Trait` 捕获哪些泛型参数 | 第 8 章 |
| **unsafe extern 块** | `extern` 块必须加 `unsafe` 关键字 | 第 19 章 |
| **unsafe 属性** | `#[no_mangle]` 等改为 `#[unsafe(no_mangle)]` | 第 19 章 |
| **unsafe_op_in_unsafe_fn** | unsafe fn 内部也需要显式 `unsafe {}` | 第 19 章 |
| **Future/IntoFuture 入 prelude** | 不再需要手动 import Future | 第 14 章 |
| **async closures** | `async \|x\| { }` 语法 | 第 10 章 |
| **async fn in traits** | trait 中可以定义 async 方法 | 第 14 章 |
| **尾表达式作用域优化** | 临时值在局部变量之前释放 | 第 3、4 章 |
| **禁止 static mut 引用** | 改用 `&raw mut` 获取原始指针 | 第 19 章 |
| **宏 fragment 变更** | `expr` 也匹配 `const { }`，缺少 specifier 是硬错误 | 第 16 章 |

### 版本要求

本书所有代码使用 **Rust 2024 Edition 语法**，要求 Rust 版本 **≥ 1.85.0**（推荐使用最新稳定版）。

检查你的版本：
```bash
rustc --version
# 应该显示 1.85.0 或更高
```

如果版本过低：
```bash
rustup update
```

## 如何使用本书

### 学习方法

1. **不要死读**。每学完一节，打开编辑器亲手敲一遍代码示例。Rust 是写会的，不是看会的。
2. **拥抱编译错误**。Rust 编译器以"友好"闻名。当你看到错误信息时，不是"你做错了"，而是"编译器在教你"。仔细阅读每一条——它在告诉你为什么这样不安全、怎样修改。
3. **先理解为什么，再记语法**。Rust 的每个规则都有其设计理由（比如所有权是为了防止 double free）。当你理解了原因，语法自然就记住了。
4. **按顺序阅读**。本书的章节安排要求前面的知识作为基础。跳到后面很可能会看不懂。

### 代码示例的使用

每章都包含可以运行的代码示例。你可以在本书的配套项目中找到它们：

```bash
git clone <项目仓库>
cd rust_lerning
cargo run    # 运行所有示例
```

### 遇到困难时

- **编译器报错看不懂？** 把错误信息完整读一遍。Rust 的错误信息通常包含问题描述、原因分析和修改建议，比很多语言的教科书还详细。
- **概念理解不了？** 回到相关章节重新读。所有权、生命周期这些概念需要多次接触才能真正内化。
- **还是不理解？** 去 [users.rust-lang.org](https://users.rust-lang.org/) 或 Rust 中文社区提问。

## 与其他语言的思维转换

不同背景的读者需要不同的思维转换。以下是几个关键的"范式转换"：

| 如果你来自 | 你需要适应 |
|-----------|-----------|
| C/C++ | 放弃手动 malloc/free，信任编译器。**编译器比你以为的更聪明。** |
| Java/C# | 放弃继承和 null。用 Trait 组合行为，用 `Option<T>` 表达缺失。 |
| Python/JS | 放弃动态类型的灵活性，接受编译期的"束缚"。**这些束缚是生产力，不是限制。** |
| Go | Rust 的并发模型更丰富（async + 线程 + 消息），但学习曲线更陡。 |

### 最重要的心态转变

> **把编译器当作队友，而不是敌人。**

在 Python 或 JS 中，你写完代码，运行，可能崩溃。在 Rust 中，编译器在你运行之前就检查了大部分问题。你花更多时间和编译器"对话"，但换来的是——一旦编译通过，代码大概率就是对的。这不是"编译器在刁难我"，而是"编译器在帮我"。
